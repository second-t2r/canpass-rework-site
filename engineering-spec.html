2. アーキテクチャ

1つのNext.jsアプリ内に、ワーカー画面・管理画面・APIルートが同居する。外部サービス（Notion/Claude/Gemini/AssemblyAI）への鍵はすべてサーバ側（Route Handlers）に閉じ込め、クライアントには出さない。

[ブラウザ(スマホ)]
   │  fetch (Cookieセッション)
   ▼
[Next.js Route Handlers  (/app/api/*)]
   ├─ Notion API ……… 稼働/ヘルス/受託タスク/請求支払 の4DB
   ├─ Anthropic ……… チャット・議事録整形
   ├─ Gemini / AssemblyAI … 音声→テキスト
   └─ Vercel Blob …… 長尺音声の一時保管(private)

別経路:
[Claude Code フック worklog.py] ──→ Notion 稼働/ヘルスDB（SessionStart/End/UserPromptSubmit）
[cron /api/cron/rebalance] ──→ 直近ログのワーカー符号を A/B/C へ均等再分配
設定の単一の正は ~/.canpass/config.json（ローカル）＝lib/canpass-config.ts が env を優先しつつ読み込む。Vercel には ~/.canpass が無いため env が効く。

5. 認証・セッション・デモモード

  • ワーカー認証：符号＋パスコード。workers.json に sha256(passcode) を保存。本番ワーカーは WORKERS_JSON env。
  • セッション：lib/session.ts。base64url(payload).HMAC-SHA256(payload) を Cookie に。timingSafeEqual で検証・12h有効。
  • 管理者認証：ADMIN_PASSCODE ＋ 別Cookie（lib/admin-session.ts）。ロックアウトあり。
  • デモ閲覧モードreadonly：demoReadonlySyms()（env DEMO_READONLY_SYMS・既定 worker-A,B,C）に該当する符号はログイン時に session.readonly=true。/api/worklog・/api/my-billing(POST) は書き込みを抑止し、UIにデモバナーを表示。worker-A/B/Cは cron で多々良の実稼働を3分割した“見せ用”データのため、デモ操作で汚さない。

6. 稼働時間の計測（能動時間・Option B）

所要時間(分)は「実際に手を動かした時間」。連続する活動イベントの間隔が、しきい値以内のぶんだけ加算する（超過＝離席として除外）。

計測元活動シグナルしきい値上限
Webアプリ app/chat/page.tsx（作業完了）keydown/pointerdown/streaming/visibilityIDLE_MS=5分—（完了ごとにリセット）
Claude Codeフック worklog.py（ログアウト）UserPromptSubmit ハートビートIDLE_CAP_SEC=15分SESSION_CAP_MIN=480

しきい値が異なるのは信号密度の差（Webは密／フックは1往復1信号）。揃えると過少/過大計上になるため意図的に分離。

7. 集計ロジック

lib/notion-query.ts → aggregateWorkers(rows, {since, until}) が単一の正。管理画面・ワーカー本人画面・請求が共用。

  • 稼働時間に計上するのは「作業完了」「ログアウト」の能動時間のみ（workMinutes/sessionMinutesに分離）。
  • 日時 < since ∥ > until（未来日時含む）は除外。
  • 日次勤務時間 daily{date:min}・avgDailyMin・maxDailyMin。OVERWORK_DAILY_MIN=480 超で overwork=true（見守り連動）。
  • 出来高：pieces（成果物件数合計）・piecesBySkill をスキル別に集計。

8. 請求・税計算（源泉・インボイス・出来高）

lib/billing-calc.ts（純関数・クライアント/サーバ共用）。

// 時間報酬: min(h,標準)×未達単価 + max(0,h−標準)×超過単価
// 出来高:   Σ skill (件数_skill × (pieceRates[skill] ?? pieceRate))
// 報酬 base = timeBase + pieceBase   (payType: 時間 / 出来高 / 併用)
消費税  = round(base × 0.10)                         (taxable=falseで0)
源泉徴収 = base ≤ 1,000,000 ? floor(base×0.1021)
                            : floor(1,000,000×0.1021 + (base−1,000,000)×0.2042)
請求合計 = base + 消費税 − 源泉徴収                    (withholding=falseで源泉0)
適格区分 = invoiceReg(T+13桁) があれば「適格」/ なければ「免税」

契約は lib/identity.ts の contract：standardHours / rateUnder / rateOver / payType / pieceRate / pieceRates / withholding / taxable / invoiceReg（管理者のみ・WORKER_IDENTITY_JSON）。

文書フロー

  • ワーカー /billing → 納品書/請求書を作成・提出（提出済）。請求書/納品書＝ワーカー→CanPass宛。
  • 管理 請求・支払 → ワーカー別/案件別集計・承認/差戻し・支払で支払明細を自動発行（CanPass→ワーカー宛）。
  • PDFは /billing/print/[id] の @media print ＋ window.print()（日本語そのまま・依存ゼロ）。閲覧は本人 ∥ 管理者のみ（/api/billing/[id]）。
金額は自動計算の概算。確定の請求/支払は税務・経理の確認のうえ実施。源泉徴収税額は支払者（CanPass）が控除・納付。

10. プライバシー（符号・マスク・L3）

  • 記録は符号（worker-◯）のみ。符号↔実名・契約は管理者だけ（identity.ts・/api/admin/identity）。
  • 書き込み時に mask() でメール・電話・長数字を伏字。
  • 長尺音声は private Blob ＋ 処理後 del。公開URLを作らない（医療隣接＝L2/L3）。
  • AI入力は API 経由で学習対象外。送信・投稿はAIがしない（人が確認）。

12. デプロイ・運用

  • デプロイ：npx vercel --prod（CLI・作業ツリーをアップロード）。エイリアス worker-app-sooty.vercel.app。
  • 請求DB初期化：node scripts/setup-billing-db.mjs --create → invoice_db_id を config/env へ。
  • ワーカー発番：scripts/workers.mjs add|rotate|sync（符号のみ・台帳は非公開）。
  • worklog フック：.claude/skills/canpass-worklog/scripts/install.sh が ~/.claude/settings.json に SessionStart/End/UserPromptSubmit を冪等登録。
  • 段階：v0（既存DBを読んで見せる軽量版）→ Phase1（専用システム化・担当 渡邊）。
