ひとことで言うと——
ワーカーの“業務日誌”を、まとめて見る画面です。

ワーカーアプリで自動的にたまる記録（稼働・体調・タスク）を、経営者・PMが1画面で把握するためのものです。新しいシステムを足したわけではなく、同じ記録ノートを“読んで見せる”だけ。だから低コストで、すぐ使えます。AIは「誰が何をやると良いか」を提案しますが、決めるのは人です。

1全体の絵

ワーカーの記録ノート → 管理画面が読み取り → 経営者・PMが見る。
ポイントは 管理画面は記録を「読む」のが中心だということ。書き込むのは「タスクの担当・状態を変える」など最小限で、ワーカーの記録そのものは勝手に書き換えません。

3「アサイン提案」のしくみ

3つの情報を掛け合わせ、無理のない担当案を出します。
  1. 受託タスク（締切・優先度・必要スキル）を見る。
  2. 今日の稼働（誰がログイン済み・どれだけ働いたか）を見る。
  3. 今日の体調を見る。体調が低い人は「軽め」、余力のある人へ寄せる。
  4. 1つの仕事に主担当＋副担当（1.5人の冗長）が付くよう提案。
  5. 未割当・締切超過・副担当なしをアラートで表示。
  6. 提案はあくまで下案。「反映」を押すかどうかは人が判断します。

＋勤怠から請求・支払まで（業務委託の実務）

「実際に手を動かした時間（能動稼働）」を土台に、勤怠 → 請求 → 支払を一気通貫で。
  1. ワーカーアプリで能動稼働時間（離席・待ち時間を除いた実作業時間）が自動で貯まる。
  2. 「ワーカー稼働／月次・請求」で、日次の勤務時間・1日平均・最大単日を確認。働き過ぎは自動でバッジ表示。
  3. ワーカーが自分の画面（/billing）から、当月の納品書・請求書を作成して提出。
  4. 管理画面「請求・支払」に届く。ワーカー別／案件別に集計（小計・消費税・源泉徴収・請求合計・未払）。
  5. 承認し、振込後に支払を押すと、支払明細（CanPass→ワーカー）が自動発行。請求書は支払済に。
  6. 各書類は印刷ボタンでPDF保存。源泉徴収（10.21%）・インボイス（適格／免税）に対応。報酬は時間／出来高（成果物の件数×単価）／併用に対応。
働き過ぎ見守り：1日の能動稼働が一定（8時間）を超えた日は「働き過ぎ」として見守りに連動。体調ログと合わせて、無理の早期発見に使います（量のノルマは課しません）。
金額はあくまで自動計算の概算です。確定の請求・支払は税務・経理の確認のうえ実施してください。源泉徴収税額は支払者（CanPass）が控除・納付します。

4プライバシーと運用の約束

医療に隣接する事業だからこそ、いちばん大事にしています。
  • 符号で管理：稼働・体調・タスクは「worker-◯」の符号で扱います。
  • 実名は“名簿”だけ：符号↔実名と契約条件は、管理者パスコードの内側の「名簿・契約」タブでのみ見られます。ワーカー側アプリや各記録には出しません（L3）。
  • 提案のみ・確定は人：アサイン等の提案は判断材料。担当の確定は人が行います。
  • 体調を最優先に：見守りは「軽作業・休息」のため。体調を理由に量のノルマは課しません。
  • 管理者限定：この画面はパスコードの内側のみ。閲覧できる人を最小限に。
速さの工夫：一度開いた画面はキャッシュして、タブの切り替えを速くしています（最新化は裏で自動）。

5お金とシステム（ローコスト設計）

管理画面は、ワーカーアプリと同じ1つのアプリの一部です。新しいサーバーやデータベースは増やしていません追加コストほぼ¥0。記録ノート（Notion）も既存のものをそのまま使います。

  • 置き場所（ホスティング）は既存と共通。
  • 管理者パスコードで保護（ワーカー用ログインとは別系統）。
  • 費用がかかるのはワーカー側のAI利用分だけ（管理画面の閲覧自体はほぼ無料）。
